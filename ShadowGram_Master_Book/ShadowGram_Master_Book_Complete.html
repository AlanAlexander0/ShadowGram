0.1 The Problem in Plain Words

Modern scammers do not use simple scripted bots. Scammers use autonomous multi-agent AI swarms. Each bot uses a different name, a different ChatGPT bio, and a clean home Wi-Fi IP address.

Traditional fraud security inspects accounts one by one. The security system asks: "Does Account A look fake?"

Because each bot looks human in isolation, the security system approves all 50 accounts. The bots take instant micro-loans and vanish together.

Core Axiom of ShadowGram
The fraud does not live inside any single account. The fraud lives in the hidden statistical relationship between accounts.

0.2 How ShadowGram Solves the Problem: The Two-Key Architecture

ShadowGram does not evaluate accounts in isolation. ShadowGram deploys a Two-Key Defense at Form Step 2:

  1. Key 1 (Per-Session Automation Filter): Inspects low-level browser telemetry in less than 5 milliseconds. It identifies missing raw mouse-movement events, zero click-dwell variance, and automation flags. This blocks standard automated tools immediately.
  2. Key 2 (Multi-Modal Relational Graph): Tracks advanced bots that use human-emulation or operating-system inputs. It measures five layers of interaction physics: time rhythm, navigation sequence, kinetic event dynamics, semantic vector intent, and hardware entropy.
  3. Pre-KYC Denial-of-Wallet Triage: ShadowGram clusters accounts before third-party verification APIs execute. This stops attackers from exhausting expensive verification budgets (Aadhaar, PAN, and credit bureaus).
  4. Community Detection (Leiden / Louvain): It groups coordinated accounts into clusters. The Leiden algorithm ensures communities are well connected and avoids resolution limits.
  5. Verifiable "Why Card": Shows empirical statistical proof ($p < 0.001$). Bank officers can review the evidence and quarantine the syndicate with one click.

Cyber-attacks have evolved through three distinct technical generations:

  • Generation 1 (Scripted Automation, 2016): Hardcoded Python cURL scripts and static proxy lists. Fast execution, but blocked by Cloudflare TLS fingerprints and reCAPTCHA checkboxes.

3.1 System Architecture Overview

3.2 The 5 Composite Physics Layers

Layer 1: Temporal Rhythm ($S_{\text{time}}$)

Measures the inter-arrival delta $\Delta t$ between sequential form events across sessions. While unsophisticated bots attack in tight bursts ($\Delta t < 50\text{ms}$), sophisticated bots add random delays. ShadowGram counters this with a 24-hour exponential decay time-kernel (Iannucci et al., ICWSM 2026) and a Poisson arrival baseline model ($P(\text{Poisson}(\lambda_w) \ge k)$). Timing acts as one contributing vote alongside orthogonal behavioral layers.

Layer 2: Navigation Finite State Machine ($S_{\text{nav}}$)

Calculates the Longest Common Subsequence (LCS) across navigation paths (e.g. /auth $\to$ /kyc $\to$ /submit). Sessions with route similarity $\ge 0.85$ are flagged. At the field level, it tracks micro-events (focus order, paste events, and backspace rates) weighted by population rarity.

Layer 3: Kinetic Invariants & Mobile Dynamics ($S_{\text{kin}}$)

Kinetic Architecture: Event-Stream Invariants & Touch Dynamics
Raw cursor jerk at 60 Hz sampling contains measurement noise. Modern GANs can also generate curved mouse paths. In addition, more than 85% of micro-lending applicants use mobile touchscreens with no mouse cursor.

ShadowGram focuses on event-stream distribution invariants rather than raw trajectory curves:

  • Web Invariants: Measures click-dwell duration variance, pre-click pointer presence, and scroll events. Automation tools (like Playwright) leave clear missing-event signatures.
  • Mobile Touch Dynamics: On mobile screens, evaluates swipe acceleration, contact surface area variance, and stroke deceleration.

A lightweight 2D-CNN in ONNX Runtime evaluates these motion matrices in $< 10\text{ms}$ on CPU, outputting $P_{\text{synthetic}} \in [0.0, 1.0]$.

Layer 4: Dense Semantic Vector Forensics ($S_{\text{sem}}$)

Bots use LLMs to write loan explanations. The words are different, but the semantic concept is identical. We compute 384-dimensional dense vectors using local CPU model all-MiniLM-L6-v2 ($< 15\text{ms}$): 

Cosine_Similarity(A, B) = (A · B) / (||A|| ||B||) >= 0.88

Layer 5: Environmental Hardware Entropy ($S_{\text{env}}$)

Extracts non-PII hardware entropy signals: AudioContext oscillator decay, WebGL canvas render hashes, and system clock skew. Hardware entropy acts as a secondary supporting signal to avoid false positives on shared campus hardware.

3.3 Graph Community Detection (Leiden Algorithm & Adversarial Defense)

An edge $(u, v)$ is created if composite similarity $S_{\text{comp}} \ge 0.78$ across at least three layers: 

S_comp(u, v) = w_time*S_time + w_nav*S_nav + w_sem*S_sem + w_kin*S_kin + w_env*S_env
Algorithmic Upgrade: Leiden Algorithm & Boundary Repair
Traditional Louvain clustering has a known resolution limit ($O(\sqrt{2L})$) and can return disconnected communities. Advanced bot syndicates can also inject "clean" bridge accounts to lower modularity (BOCLOAK, ICML 2026).
ShadowGram Upgrade: We execute boundary graph repair (isolating anomalous bridge edges) and apply the Leiden Algorithm (Traag et al., 2019). Leiden guarantees well-connected communities and separates dense bot cliques from background traffic.

Any cluster with Modularity $Q > 0.60$ and node count $\ge 3$ is mathematically isolated as a syndicate ($p < 0.001$).

4.3 Auditable Legal SAR PDF Generation

When an officer quarantines a cluster, raw graph metrics are formatted into structured JSON and sent to the NVIDIA NIM API (Llama-3.3-70B).

To prevent LLM hallucination, the model uses constrained decoding against formal regulatory templates. It renders graph metrics into formal Adverse Action Reason Codes. Python ReportLab compiles a 2-page Suspicious Activity Report (SAR) PDF in under two seconds.

4.4 False Positive Protection & Safeguard Protocol

  1. Common-Cause Immunity Rule: External viral events (e.g. college loan drives) correlate time and loan reason. They do not correlate neuromotor hand dynamics or micro-interaction distributions. Edges require at least one common-cause-immune layer.
  2. Empirical Permutation Test: Shuffles session labels 1,000 times within the sliding window. Clusters are isolated only when the empirical $p$-value satisfies $p < 0.001$, proving coordination is not accidental.
  3. Zero Permanent Bans: ShadowGram never executes irreversible hard bans. Quarantined sessions receive an adaptive Step-Up Challenge.
  4. Friction-Free Escalation: Honest users complete a fast verification check (1-rupee UPI penny-drop or Account Aggregator consent) in ten seconds. Headless automated bots fail and abort.

8.2 Why Haven't Existing Fraud Vendors Built This Solution?

During stress testing, we investigated why established fraud vendors have not solved this specific micro-lending problem. Five structural, economic, and technical barriers protect ShadowGram's market position:

1. The Consortium Business Model Conflict (The "Data Magnet" Trap)

Major identity providers (BioCatch, Sift, LexisNexis ThreatMetrix) build their businesses on global data consortiums. Their revenue requires customers to upload private user data to centralized cloud systems. They sell enterprise subscriptions costing $100,000 to $500,000 per year. They cannot sell a lightweight, local, on-premise container that runs inside a lender's private network without sharing data.

2. The Post-Submission / Transaction-Centric Legacy Bias

Most enterprise banking fraud platforms were designed for transaction fraud (credit card theft, wire fraud, and account takeovers). They sit behind the core banking database. They are blind to user micro-interactions at Form Step 2. They only evaluate an applicant after the applicant clicks "Submit" and expensive verification APIs have already run.

3. The $O(N^2)$ Pairwise Computational Wall

Calculating pairwise similarity across 5 physics layers for 100,000 sessions requires nearly 5 billion comparisons. Traditional servers crash under this load. Consequently, legacy vendors run graph clustering as an offline batch process overnight. ShadowGram solves this with multi-stage blocking (approximate nearest neighbor search and time-window bucketing), keeping graph construction fast ($O(k \cdot N)$) and in-memory.

4. The Emerging-Market "Denial-of-Wallet" Blind Spot

Western fraud vendors designed software for US and European markets where credit checks are billed on flat enterprise tiers. In India and Southeast Asia, digital lenders use transactional verification APIs (Aadhaar e-KYC, PAN validation, face liveness, and credit bureau pulls) that cost ₹33.50 to ₹118.50 per applicant. Western systems let bots exhaust the lender's verification budget before evaluating fraud. ShadowGram stops this drain at Form Step 2.

5. The Regulatory Black-Box Paralyzation

Lenders fear unsupervised clustering algorithms because banking laws (ECOA Regulation B) prohibit unexplained loan denials. Legacy vendors avoided unsupervised clustering for credit applications. ShadowGram overcomes this barrier by pairing cluster isolation with a non-punitive Step-Up Challenge (1-rupee UPI penny-drop) and a statistically verifiable "Why Card" that auditors can re-run.

APP Master Glossary & Reference Bibliography

Master Glossary (ASD-STE100 Technical Terms)

  • Two-Key Defense: A security architecture with two stages. Key 1 detects automation artifacts on single sessions. Key 2 detects coordinated behavior across sessions using an in-memory graph.
  • Denial-of-Wallet (DoW): An adversarial attack that floods an application funnel to force the target organization to pay excessive third-party verification API fees.
  • Event-Stream Invariants: Statistical properties of user input streams (e.g. click dwell duration variance, presence of pointer events before clicks) that automated tools fail to replicate.
  • Leiden Algorithm: A graph community detection method that guarantees connected communities and addresses the modularity resolution limit.
  • Common-Cause Immunity: A safeguard rule requiring at least one graph edge layer to be immune to external viral events (such as synchronized marketing campaigns).
  • Empirical Permutation Test: A statistical method that shuffles session labels 1,000 times to calculate an exact empirical $p$-value ($p < 0.001$).
  • Why Card: An explainable user interface window that displays verifiable factual evidence explaining why accounts were grouped into a cluster.
